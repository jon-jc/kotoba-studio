# Agent Note：已配置的提供方与会话模型控件

Status: implemented

[English](2026-09-12-configured-provider-selectors.md) | 中文

## 问题

注册顺序使 DeepSeek 排在已保存凭据的提供方之前。混合模型菜单不便选择提供方，原生语音目录也将所有已注册路由视为已配置。

## 决策

宿主目录通过提供方的已解析设置和凭据描述添加可选的 `configured` 元数据。客户端仅接收可用状态。凭据服务缺失或描述读取失败时，就绪状态保持未知。无需密钥的配置可用；缺少配置则未配置。稳定排序将已配置分组排在前面。设置控制器使用既有凭据就绪判定进行相同排序。

每个会话具有独立的提供方和模型控件。切换提供方通过既有会话选择命令选择其首个公布的模型；模型菜单只显示该提供方的模型。推理强度由模型定义。仅在没有历史请求或显式会话选择，且没有更新的选择或连接代次介入时，目录加载才替换未配置的部署默认值。已有会话保留其选择。原生语音依据目录就绪状态选择已配置的提供方，并避免携带其他提供方的模型 ID。

## 验证

宿主测试覆盖自定义密钥引用、刷新和凭据读取失败。客户端测试覆盖提供方排序、模型过滤、推理强度、选择失败及独立会话选择。原生测试覆盖已配置提供方回退和自定义模型 ID 保留。这些控件不需要调用外部模型。

## 影响

已配置标记只表示凭据存在，不代表远端服务已验证凭据。未知就绪状态仍可选择。提供方目录失败仍会显示并支持重试。排序稳定，保存其他密钥不会改变既有会话选择。

## 考虑过的替代方案

硬编码 OpenAI 优先只是替换厂商偏好，且忽略自定义网关。仅按适配器注册排序无法区分已保存的凭据。混合模型菜单需要浏览无关提供方，因此 composer 分离提供方和模型选择，同时保留既有会话控制器。

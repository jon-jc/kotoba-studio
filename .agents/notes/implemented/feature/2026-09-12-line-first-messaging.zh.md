# Agent Note: LINE 优先的桌面消息中心

Status: implemented

[English](2026-09-12-line-first-messaging.md) | 中文

## 问题

Kotoba 需要为英语和日语团队提供消息入口，同时避免将不可信的入站消息自动当作计算机指令。仅有连接表单无法解决凭据存储、重复消息、会话状态和不明确的投递结果。

## 决定

原生界面按 LINE、Slack、Discord、Telegram 排序，每个平台保存一个连接。明确启动的网关拥有进程锁、平台适配器和可选的签名 LINE HTTP 接收器。配置编辑使用同一把锁。Windows DPAPI 保护凭据；带架构版本的 SQLite 保存文本、草稿、别名、未读水位和投递状态。网关在托盘中持续运行，并在应用关闭前停止。通知需要主动启用，只包含数量。

LINE 对有大小限制的原始请求体验证签名，在确认之前提交允许发送者的消息。公开 HTTPS 入口由用户的隧道或反向代理提供。Telegram 使用长轮询，并拒绝已有 Webhook。Slack 和 Discord 为新消息轮询保存检查点，包含分页追赶；历史按平台时间排序。发送者列表为必填，LINE 和 Telegram 群组另有访问限制。平台标识为机器人的消息被忽略。

只有点击发送才会排队回复。HTTP 请求前记录发送中，成功后记录平台接受。发送中的崩溃或超时留下结果不明的记录，绝不自动重发。中断的待发送记录变成失败。恢复操作经过确认后将文本放回草稿。LINE 携带 UUID 重试键；Discord 禁用提及，Slack 发送字面文本。API 接受不代表收件人已收到或已读。

AI 回复准备为现有语音智能体路由创建待审核请求。消息回复使用新的、自有的 SDK 会话，并在成功或失败后关闭；不复用普通语音会话。生成的回复只能在捕获的上下文未变时导入原始会话。导入不会发送。禁止工具的文字是提示要求，并非新的权限策略；智能体仍保留现有访问控制。

## 影响

这是 Windows 文本消息中心，不替代完整消息客户端。不同步附件、语音、编辑、删除或表情反应。Slack 不导入线程回复；Discord 线程需要指定其频道 ID；Telegram 话题保持独立。本地历史为明文，凭据经过加密。导出和交接最多包含最新 200 条本地消息。真实平台账户行为与模型回复质量需要另行配置凭据，不能由测试夹具证明。

## 考虑过的替代方案

嵌入 Hermes 运行时会重复 Kotoba 的智能体所有权和提供商路由。原生适配器使用各平台公开 API，并借鉴 Hermes 的网关设置、发送者授权和投递账本。自动远程执行智能体需要另外设计权限与审批流程。静默重试不明确的发送可能造成重复消息，因此恢复必须明确审核。

## 验证

测试覆盖 Windows 凭据往返、无明文密钥、签名篡改、发送者和群组授权、重复回调、持久化确认、请求大小限制、发件箱崩溃恢复、无密钥错误、分页检查点、未读到达跟踪、独占网关锁以及拒绝未来架构版本。在分配的端口上启动并停止真实的回环 LINE 接收器。原生测试覆盖 LINE 优先顺序、纯文本显示、草稿持久化、绑定来源的 AI 回复导入和新 SDK 会话清理。外部发送使用模拟传输，原生截图使用虚构且未发送的示例。

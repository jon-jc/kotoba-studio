# Agent Note: Windows 托盘生命周期与应用标识

Status: implemented

[English](2026-09-10-windows-tray-identity.md) | 中文

## Problem

没有显式应用标识时，Windows 可能把从源码启动的窗口归到 Python。关闭桌面也会终止用户希望保留在后台的工作区。

## Decision

Kotoba 在创建 Qt 界面前设置 `KotobaStudio.Desktop`；安装的快捷方式使用相同标识，并显式引用同捆的 Kotoba 图标。应用级图标同时用于原生对话框和系统托盘。

托盘可用时，关闭主窗口会隐藏窗口，保留运行时和工作区状态。本地化托盘菜单可恢复窗口、打开语音工作区或退出。退出沿用现有进程清理路径。原生录音或处理进行中会拒绝关闭和退出，并恢复窗口。托盘不可用时，关闭会退出，避免留下无法恢复的后台应用。

## Alternatives considered

**保留 Windows 推断的标识。** 仅嵌入可执行文件图标不足以给源码启动分配独立任务栏分组。共享显式标识使进程和快捷方式保持一致。

**始终隐藏窗口。** 缺少托盘时，应用没有恢复入口。因此关闭时会检查托盘是否可用。

## Consequences

用户通过托盘菜单显式退出。不会创建登录启动项。已有 Python 固定项可能需要重新固定安装后的 Kotoba 快捷方式。原生工作流测试覆盖状态保留、恢复、本地化、录音期间拒绝关闭、托盘丢失和清理；打包验证可用 `--tray` 要求真实 Windows 托盘。

# Agent Note: 并行智能体工作区

Status: implemented

[English](2026-09-12-parallel-agent-workbench.md) | 中文

## Problem

桌面只有一个浏览器客户端，切换会话会替换可见对话，使独立草稿和提供商活动难以跟踪。多个浏览器客户端若共享选择存储，就会恢复或覆盖同一个所选会话。

## Decision

左侧列表管理连接到现有已认证 Harness 主机的独立常驻浏览器客户端。每次只显示一个会话。各客户端使用不同的持久浏览器配置，主配置保留原有路径。提供商选择仍由会话现有的 ModelDirectory 负责，智能体执行仍使用现有循环。桌面存储视图 ID、名称、所选会话 ID 和子智能体地址，不存储凭据或运行时 URL。文档创建脚本跨临时回环端口恢复选择。主机会话列表就绪后才持久化选择。

框架通过桌面数据属性投影会话 ID、列表就绪状态和运行状态；模型组件提供提供商和模型 ID。原生轮询将这些值序列化为 JSON，每个视图最多保留一个未完成读取。桌面导航事件用原生列表替换网页侧栏；History & workspaces 恢复现有侧栏，Back to agents 无需重新加载即可返回。仅浏览器客户端保留正常布局。

搜索、重命名、键盘切换、后台完成提示及英日标签由原生列表负责。切换视图使待处理的语音粘贴失效。关闭视图需要确认，会释放浏览器，但保留已接受的主机任务和已保存会话。关闭应用仍使用既有的运行时关闭语义。

## Alternatives considered

**分屏会话**被用户否决。**独立替代智能体循环**会丢失 Harness 工具、插件、审批和持久事件处理。**共享浏览器选择配置**会通过存储耦合聊天。**每个视图启动新主机**会重复模型进程和凭据配置，却不提供必要能力。

## Consequences

每个打开的智能体都会占用常驻浏览器内存。它们共享配置的主机、凭据、工具和文件系统权限；浏览器配置不是安全沙箱。有冲突的文件编辑仍需使用不同工作区。用户可以从历史中主动选择现有会话，因此两个视图可能观察同一主机智能体。测试覆盖同时进入提供商、独立取消和会话内容、原生导航与存储、子智能体地址恢复、延迟回调以及仅显示一个会话。真实桌面检查覆盖两种语言的 Harness 组合界面；提供商测试使用确定性适配器，不调用付费 API。

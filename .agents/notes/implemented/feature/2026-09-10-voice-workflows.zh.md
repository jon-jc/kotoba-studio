# Agent Note: 桌面听写与本地会议参考

Status: implemented

[English](2026-09-10-voice-workflows.md) | 中文

## Problem

短时应用录音和窗口内快捷键无法支持向其他桌面应用听写，也无法形成持久的会议参考资料。单一多语言默认模型不能满足英语与日语的不同需求。

## Decision

[音声工作区](../../../../python/voice/src/kotoba/desktop.py)提供明确的处理模式和按语言选择的默认模型。英语通过 sherpa-onnx 使用 Parakeet Unified，日语使用官方 Kotoba-Whisper v2 CTranslate2 转换，自动语言检测使用多语言 Whisper Turbo。本地推理只加载已下载文件；分词器缺失时报错，避免隐式网络回退。模型下载由用户明确触发。日语使用片段时间戳，因为蒸馏模型的逐词对齐会使原生运行时崩溃。

[全局听写](../../../../python/voice/src/kotoba/global_dictation.py)将 OpenWhispr 的 Windows 粘贴行为适配到 Qt 原生事件过滤器。用户选择启用快捷键，退出时释放注册。粘贴检查录音时的前台窗口与进程；目标改变或修饰键未释放时拒绝输入。结果替换剪贴板，不发送 Enter。存在不确定性的结果保留供审阅。

[会议捕获](../../../../python/voice/src/kotoba/meetings.py)适配 OpenWhispr 的会话所有权和最终转录持久化模式。捕获回调提交有界音频片段；推理先提交带时间戳的文字，再报告完成。停止流程等待捕获静止、处理队列并保存尾部。队列溢出和录音源失效产生明确的不完整记录。本地 SQLite 提供笔记、双语字面搜索、可审阅重点、Markdown 导出、删除和中断恢复。交给智能体时只创建草稿，不直接执行由转录派生的操作。

录音、音频导入和会议捕获在打开输入前进行离线模型准备。工作线程结束后，缺失模型的类型化结果打开明确的设置提示。下载不会自动开始录音，也不保留桌面粘贴目标。输入语言独立于界面语言保存。启动时只显示聊天。

原生语音智能体及其设置读取实时 Harness 模型目录和提供者配置，避免独立列表与聊天配置不一致。本次会话的密钥使用所选路由的凭据引用；切换提供者会清除旧密钥及模型选择。未配置的路由仍可发现，并显示设置说明；已配置的路由支持自定义模型 ID。

## Alternatives considered

在 Qt 桌面中嵌入完整 Electron 渲染器会重复应用生命周期、存储和更新基础设施。因此集成复用原生捕获代码、模型定义和适配的生命周期逻辑，并保留署名。自动粘贴到替代前台窗口或自动回退云端会违背用户选择的目标和处理模式。

## Consequences

全局听写和应用捕获仅针对 Windows。录音源标签不是说话人分离，关键词重点不是生成式摘要，也不保存原始音频以供崩溃恢复。已完成片段可以恢复，当前及排队音频可能丢失。云端语音通过独立、明确选择的自有密钥上传路径处理。[工作流指南](../../../../python/voice/VOICE.md)说明隐私边界、限制和模型选择；[评估记录](../../../../python/voice/evaluation/README.md)区分字幕一致性与经验证的准确率。

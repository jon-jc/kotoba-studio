# Agent Note: 原生语音会话

Status: implemented

[English](2026-09-13-native-voice-conversations.md) | 中文

## 问题

听写与操作系统的文字转语音无法提供共享的原生音频会话。Kotoba 需要在同一会话中处理语音与文字，同时避免默默授予音频模型计算机操作权限。

## 决策

Python 桌面端拥有一个由用户明确启动的语音连接。提供方适配器实现 OpenAI Realtime、Gemini Live 和 Grok Voice。具有缓冲上限的工作线程交换 PCM 音频与归一化的转写事件；现有 Harness 和订阅代理保留各自的执行与权限模型。确认后的文本交接到草稿，不自动提交。原始音频仅临时存在，不重放，也不保存为 Harness 会话。

默认按住说话。免提使用服务端语音检测，麦克风初始为静音。关闭面板或应用会停止连接，退出等待工作线程完成。会话上限为 30 分钟，连接配置与关闭有超时，输入输出队列有界，不自动重试或切换提供方。Windows WASAPI 可使用系统格式转换器。由于没有声学回声消除，建议使用耳机。

语音面板按优先级接受仅本次使用的密钥、用户明确保存的 Windows DPAPI 密钥、对应提供方的环境变量。不会为 Harness 凭据控制器新增读取秘密的 RPC。切换提供方会清空输入的密钥。错误仅暴露固定分类，不暴露 URL、请求头或提供方载荷。文字与音频共享提供方会话；Gemini 当前模型仅允许将 client content 用于初始历史，因此持续的文字输入使用 realtime input。

## 考虑过的替代方案

组合本地转写、文本生成与语音合成可覆盖更多提供方，但不属于原生语音到语音。通过 RPC 暴露已保存的 Harness 密钥会削弱现有单向凭据边界。复用订阅代理登录会错误暗示此类账号授予语音 API 权限。

## 影响

语音 API 凭据需要单独设置。语音模型不能操作文件或工具；用户通过选定代理确认并发送可执行的文本。OpenAI 与 Grok 的中断会清空播放并在服务端上下文截去未播放的音频。Gemini 的停止播放不取消服务端生成，后续语音或文字输入产生原生中断。转写仅在内存中保留，直到新会话或退出，最多 200 条。切换语言通过 QScrollArea.takeWidget 保留语音组件，防止两个滚动区域同时拥有同一组件。

## 验证与限制

无需密钥的测试覆盖三个协议适配器、最终转写替换、麦克风门控、播放上限、脱敏错误、模拟传输的建立与关闭、提供方隔离的密钥、确认后的交接、隐藏时停止，以及实际显示时的语言重建。原生 Windows 预览验证面板布局。这些测试不能证明付费提供方会话、账号权限、耳机声学效果或干净机器的音频兼容性。用户指南说明这些限制，并区分云端实时语音和本地听写。

# Agent Note: 双语团队交接

Status: implemented

[English](2026-09-12-bilingual-team-handoffs.md) | 中文

## 问题

英语和日语团队成员需要区分原始会议证据、翻译摘要和已确认承诺。普通转录没有单独的翻译审核或负责人记录。

## 决定

Kotoba 将双语交接与会议转录分开保存。交接包含原文、术语、可编辑的英文和日文摘要，以及带负责人、日期、进度、引用和审核标记的决定、行动或问题。导入会议会创建独立副本。修改原文或术语会重置所有审核；修改工作项会重置该项审核，进度变更除外。SQLite 架构版本 1 和乐观修订号保护本地持久化和多个窗口的并发编辑。

AI 辅助在现有语音草稿中准备未发送的请求；用户选择模型，通过现有智能体发送，再导入 JSON 回复。请求要求不使用工具，但不会替换智能体的访问策略。向云端提交仍需明确操作。原文和术语指纹拒绝过时的回复。解析字段有大小限制，每个导入工作项必须包含与原文完全一致的引用。这些检查不能证明翻译准确性或语义蕴含，因此导入内容均为未审核。替换已有翻译内容需要确认。

## 影响

复制和 Markdown 导出保留原文及审核标签。没有自动执行任务、消息发送、远程同步或共享账户服务。关闭窗口后本地数据保留。存储冲突保护已保存的新数据并报告未保存的编辑。

## 替代方案

静默翻译会议片段会混合原始证据与模型输出。根据推测意图自动指派负责人会使未确认的承诺看似已达成。独立启用工具的后台智能体会重复路由和授权。明确的请求与导入流程保留现有模型选择和审核步骤，但增加了交互成本。

## 验证

所属模块测试覆盖持久化、并发修订、拒绝未来架构版本、格式错误的响应、缺失引用、过时的原文与术语指纹、导出的不确定性标签，以及原生编辑器的审核失效。英文和日文原生窗口预览使用手动编写的示例，不是模型质量证据。这些检查不发送外部模型请求。
